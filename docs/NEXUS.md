# Optional Nexus visit and return

Plain conversation remains sufficient to capture, retrieve or request a reading. An optional Nexus visit is a selected exploration over one immutable bag version; Nexus owns the encounter workflow. The receiving contract is [Nexus #33](https://github.com/compaii/daimon-nexus/issues/33) and its maintained `docs/wiggle-materials.md`.

Use `prepare-visit` with explicit bag/revision, visit/table IDs, purpose, selected participants and individual recipients, selected-by attribution and the actual selection source. It writes a private handoff containing the complete selected package; no import, publication or model call occurs. For a non-public bag the input audience must remain identical. Unsupported receiving scopes refuse rather than broaden. IDs and content digest are shared by both sides.

After an observed encounter, `retain-visit` stores the exact handoff and an attributed receipt with observed date/source, status and table URI. Outputs use explicit bucket/URI, authorship and provenance. Choose a new receipt ID for a later return, retaining the same original visit identity and input. These records are separate from raw input and included in private full-history export/recovery. Result links retain the target service's own access requirements.

A selected Jpsh! activation may be recorded with author/date/source/reason. Recording it creates no project, plan or external effect. Those effects need their normal explicit human-selected destination and observed receipts. Output enters bag input only through a separately selected ordinary capture, never because a visit produced it.

The actual agent qualification uses the real published revision 1, an attributed current-body question and considered synthesis, the owning Nexus integration issue as output destination and a later return to the same input/result. No human attendance, native reply, new project activation or complete Mini App acceptance is fabricated. Production integration and actual chosen human use remain tracked in #6.
