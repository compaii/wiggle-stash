# What a bag brings to mind — selected development direction

Nicolás clarified the intended reading on 2026-10-13: opening a bag should reveal what CompAII knows that relates to it, where each item comes from, and briefly why it connects. The main result is a source-attributed inventory of associations. New elaboration is brief and optional, reserved for strong points that emerge. This refines the original reading roadmap before any remaining Nexus work. This document describes the next increment; it does not claim implementation.

## Foreground traversal

1. Select the same immutable bag package/version the human sees. Read every selected item and its representation, including original media and attributed derivative coverage. Keep human input unchanged.
2. Use its subject, names and selected material to navigate relevant being-level HMK records, linked documents, maintained project sources and other selected bags. Follow discovered relationships into relevant sources; the bag's implementation repository is not the default limit of the topic. Use existing authorized recall and project retrieval rather than introducing another memory store.
3. Read the original evidence for each retained association, following all pages with the retained revision. Distinguish a memory of a conversation from its unavailable original transcript; preserve attribution, dates, corrections and uncertainty. Search rankings and top results are navigation, not the complete inventory.
4. Retain each inspected relevant item with a stable source identity/version, original title, type, date, author/provenance, locator or selected faithful excerpt, and a brief reason for its relationship to the bag. Direct references, remembered relationships and current interpretations must remain recognizable. Deduplicate repeated representations without erasing their origins.
5. State which sources/routes were searched, what was inspected, limits/truncation and unavailable evidence. Preserve the complete identified relevant inventory as reachable content; grouping and emphasis cannot silently hide the remaining items. The result represents what was recovered within this traversal, not a proof of all possible knowledge.
6. Add zero to three short observations only when strong points emerge. No required essay, generic synthesis, automatic project creation or automatic addition of discovered context to the bag's raw input.

## Human and AI view

Keep the accepted Resonancia design. Show the selected bag and date, then the associations and their origins. Useful groups may include remembered conversations, documents/materials, related bags and developments. Each item answers what it is, where it comes from and why it connects. Opening its basis retains the source/version that was actually consulted. Original input remains separately accessible.

The optional short observations follow the inventory. Reading history explains generation occasion and actual changes, distinguishing a revisited source from a new human note. The zero-reading state supplies a conversational request naming the selected bag; a webpage visit itself does not invoke a model. The same selected inventory, provenance, versions and observations are retained in the AI-accessible edition. Older essay-style readings remain historical records with their original method.

A Ratios bag surfacing a remembered discussion, a referenced document and a relationship to Beacon or Phideus is an illustrative qualification target, not evidence that those associations have already been retrieved. Do not create HIT/Ratios bags, invent links or import entire conversations merely from this example. Start qualification on an existing selected bag with real authorized evidence.

## Cheap change checks

Preserve the bag digest and all consulted source checkpoints. Extend supported cheap adapters to compare HMK record revisions and selected project/document versions without rereading every source or generating an interpretation. Retain the discovery queries/routes so a bounded navigation-only repeat can identify new candidates; candidate inspection belongs to a requested new traversal.

Current installed HMK MCP supports bounded lexical search plus revision-guarded paged reads/history. It has no metadata-only revision/change-feed action. Design or extend that capability in its owning repository before claiming a cheap complete memory-version check. Existing hybrid retrieval remains available for recall; lexical misses alone cannot establish absence. Unknown/truncated discovery, inaccessible sources and changed revisions remain explicit. No freshness claim extends beyond the checked scope.

There is no observer, timer, private-session import, cross-being pool or automatic publication. Foreground recall does not grant disclosure. Use the existing chosen audiences for the derived inventory too; a public raw bag may have a separately selected private reading when associations include private memories.
